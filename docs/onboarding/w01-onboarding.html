Part A · 문제 정의

우리가 예측하려는 것

단백질 하나와 화합물 하나를 주면, 이 둘이 결합하는가를 답한다.

입력 1

단백질

MRPSGTAGAALLALLAALCPASRA
LEEKKVCQGTSNKLTQLGTFEDHF…

아미노산 20종이 사슬로 이어진 것. 이 문자열이 3차원으로 접혀서 기능을 한다.

입력 2

화합물

CC(=O)Oc1ccccc1C(=O)O

약이 될 수 있는 작은 분자. 원자 수십 개짜리. 이건 아스피린이다.

출력

결합 여부, 그리고 — 이 프로젝트의 진짜 질문 — 확신의 정도

정확도가 아니라 모델이 자기가 틀릴 때를 아는가가 우리 주제다. 오늘은 그 질문을 던지기 위한 어휘를 깐다.

Part A · 01 · 어휘

단백질의 해부학

잔기
residue
사슬에 들어간 아미노산 하나. 순서대로 번호가 붙는다 — Lys745 = 745번째 잔기, 라이신. 단백질 하나에 수백~수천 개.
타겟
target
약이 작용시키려는 단백질. 같은 분자를 기능 얘기할 땐 "단백질", 신약 맥락에선 "타겟"이라 부를 뿐이다.
pocket
결합 부위
표면의 오목한 홈. 리간드가 들어가 앉는 곳. 보통 10~30개 잔기가 둘러싼다. 단백질 전체 중 극히 일부.
리간드
ligand
pocket에 결합하는 작은 분자. 우리 맥락에선 약물 후보 화합물.
도메인
domain
독립적으로 접히는 단위. 큰 단백질은 도메인 여러 개가 이어져 있다.
왜 pocket만 따로 보나 — 단백질 전체가 잘 예측돼도 pocket 부분이 부정확하면 결합 예측에 쓸모없다. 반대도 성립. 우리 난이도 좌표는 전부 pocket 기준으로 계산된다.
Part A · 02 · 어휘

entry — 데이터베이스의 레코드 한 줄

"entry"는 생물학 용어가 아니라 DB 용어다. 어느 DB의 entry인지가 매번 다르다.

DBentry 하나 = 식별자 예우리 용도
UniProt단백질 하나 (서열 + 주석)P00533 (EGFR)타겟의 기준 ID
PDB실험으로 푼 구조 하나1M17실험 구조 존재 여부
AlphaFold DB예측 구조 하나AF-P00533-F1구조·pLDDT 원천
ChEMBL측정 하나 또는 화합물 하나CHEMBL941친화도 + 출처 논문
BindingDB(단백질, 화합물, 측정값) 하나—우리 주 데이터
Pharos타겟 하나 + 연구 성숙도 등급EGFR / Tclin난이도 좌표 ⑤

같은 단백질, 여러 entry

EGFR 하나에 UniProt entry는 1개지만 PDB entry는 수백 개다 — 서로 다른 리간드, 서로 다른 변이체, 서로 다른 조각. ID 매핑이 큐레이션 트랙 일의 절반이다.

apo / holo

구조 entry를 부르는 두 이름.
apo = 리간드 없이 푼 구조.
holo = 리간드가 결합된 채로 푼 구조.
holo가 있으면 그 타겟은 사실상 이미 풀린 타겟이다.

Part A · 03 · 어휘

결합 친화도 — 얼마나 세게 붙나

Kd
해리 상수. 단위 M(몰). 작을수록 세게 붙는다. 1 nM이 100 nM보다 100배 강하다
Ki
저해 상수. 개념상 Kd와 같은 자리를 쓴다
IC50
활성을 절반으로 떨어뜨리는 농도. 실험 조건에 더 민감해서 Kd/Ki보다 비교가 어렵다
pKd
-log10(Kd in M). 클수록 세게 붙는다. 로그라서 회귀에 쓰기 좋다
KdpKd해석
1 nM9매우 강함 — 약이 될 만함
100 nM7강함 — 흔한 판정 기준선
10 µM5약함 — 실용성 낮음
이진 분류로 바꿀 때의 함정
BindingDB에는 측정된 쌍만 들어있다. 대부분 실제로 붙는다. "안 붙음"이라는 라벨이 원래 없다.

그래서 pKd ≥ 7 = 결합, < 7 = 비결합처럼 임계값으로 자른다. 이때 "비결합"은 안 붙는 게 아니라 약하게 붙는 것이다. 논문에 이걸 명시해야 한다.

4주차에 같이 얼릴 것

임계값(7), 어떤 측정치를 우선할지(Kd > Ki > IC50), 같은 쌍의 중복 측정을 어떻게 합칠지(중앙값). 셋 다 결과를 바꾼다.

Part B · 01 · 분자

SMILES — 분자를 문자열로

원자는 글자, 결합은 기호, 고리는 숫자 짝으로 닫는다. 소문자는 방향족(aromatic) 원자.

분자SMILES읽는 법
에탄올CCO탄소–탄소–산소. 수소는 생략(자동 추론)
벤젠c1ccccc1방향족 탄소 6개, 1과 1이 만나 고리를 닫음
아스피린CC(=O)Oc1ccccc1C(=O)O()는 가지, =는 이중결합
카페인Cn1cnc2c1c(=O)n(C)c(=O)n2C고리 두 개가 원자를 공유해 융합

canonical SMILES

같은 분자를 여러 문자열로 쓸 수 있다. RDKit이 규칙에 따라 하나로 정규화한다. 중복 제거와 데이터 누출 점검은 반드시 정규화된 형태로 한다.

SMILES가 담지 않는 것

3차원 좌표가 없다. 어떤 원자가 어떤 원자와 붙어 있는지(연결)만 기록한다. 모양은 슬라이드 14 참조.

Part B · 02 · 도구

RDKit — 분자를 다루는 표준 도구

오픈소스 케모인포매틱스 라이브러리. C++ 코어에 Python 바인딩. BSD 라이선스라 상업 사용도 자유롭다.

읽고 정규화

SMILES·InChI·SDF·mol 파일을 파싱하고, canonical 형태로 정규화하고, 유효성을 검사한다

숫자로 변환

fingerprint, descriptor(분자량·logP 등), scaffold 추출, 부분구조 검색

3D와 그림

Part B · 03 · 어휘

분자의 부위 이름

고리
ring
원자들이 닫힌 순환을 이루는 부분. 벤젠은 탄소 6개짜리 고리 하나.
고리 시스템
ring system
원자를 공유하며 융합된 고리들의 묶음. 나프탈렌은 고리 2개가 한 변을 공유하므로 고리 시스템은 1개. 위 그림은 공유하지 않으므로 고리 시스템 2개.
linker
고리 시스템끼리 잇는 사슬. 양쪽 끝이 고리에 붙어 있다.
곁사슬
치환기
골격에 매달린 가지. 끝이 막다른 길이다. 이게 linker와의 유일한 차이다.
용어 충돌 주의 — 단백질에서 "곁사슬"은 잔기의 R기(각 아미노산을 구별하는 부분)를 뜻한다. 분자에서 쓰는 "곁사슬"과 완전히 다른 것이다. 문맥으로 구분해라.
Part B · 04 · 표현

Morgan fingerprint — 원리

각 원자를 중심으로 반경 r 안의 부분구조를 훑고, 그걸 해시해서 정해진 길이의 비트를 켠다.

1 · 훑기

원자마다 반경 0(자기 자신), 1(직접 이웃까지), 2(두 칸까지)의 환경을 뽑는다. radius=2가 사실상 표준이며 이걸 ECFP4라 부른다

2 · 해시

각 부분구조를 정수로 해시하고 fpSize(보통 2048)로 나눈 나머지 위치의 비트를 1로 켠다

3 · 결과

길이 2048인 이진 벡터. 어떤 분자든 같은 길이가 되므로 그대로 모델 입력이 된다

왜 radius 2가 표준인가 — 반경 0은 원소 종류만, 반경 1은 작용기 정도, 반경 2는 "이 원자가 어떤 화학적 맥락에 있는가"를 담는다. 더 키우면 부분구조가 너무 특이해져서 분자끼리 겹치는 비트가 사라진다.

해시 충돌은 정상이다. 서로 다른 부분구조가 같은 비트를 켤 수 있다. 2048비트면 실무상 문제되지 않는다.

Part B · 05 · 표현

Morgan fingerprint — 에탄올로 직접

CCO. 원자 3개: C0 — C1 — O2. (수소는 생략)

중심 원자radius보이는 부분구조해시 → 비트 위치
C00말단 탄소 그 자체h → bit 1057
C01C0 + 이웃 C1h → bit 294
C02C0 + C1 + O2 (전체)h → bit 1873
C10가운데 탄소h → bit 807
C11C1 + 양쪽 이웃 C0, O2h → bit 1552
O20산소h → bit 640
O21O2 + 이웃 C1 = 하이드록시기h → bit 222

결과 벡터 (앞 64비트만 확대)

비트 번호는 실제 RDKit 해시 결과가 아니라 설명용 예시다. 요점은 부분구조 하나가 비트 하나에 대응한다는 것. 원자 3개짜리 분자도 7개 부분구조를 만든다. 약물 크기 분자면 보통 50~120개의 비트가 켜진다.

여기서 나오는 성질 — 두 분자가 부분구조를 많이 공유하면 켜진 비트가 많이 겹친다. 다음 슬라이드의 유사도가 정확히 이 겹침을 센다.
Part B · 06 · 유사도

Tanimoto — fingerprint 위의 Jaccard 유사도

T(A, B) = |A ∩ B| / |A ∪ B|

두 분자에서 둘 다 켜진 비트 수를 둘 중 하나라도 켜진 비트 수로 나눈다. 출력 0~1.

  • > 0.85 — 사실상 같은 계열. 활성도 비슷할 가능성이 높다
  • 0.4 – 0.6 — 공통 골격은 있으나 다른 분자
  • < 0.3 — 화학적으로 남남

경계값은 관례일 뿐 물리 상수가 아니다. fingerprint 종류·크기·radius에 따라 통째로 달라진다. ECFP4 / 2048bit로 고정하고 논문에 명기해라.

난이도 좌표 ①

리간드 신규성

테스트 화합물 하나를 잡고 학습셋 전체와의 최대 Tanimoto를 구한다. 낮을수록 모델에게 처음 보는 분자 = 어려운 문제.

from rdkit.Chem import DataStructs
sims = DataStructs.BulkTanimotoSimilarity(fp_test, train_fps)
coord1 = max(sims)
Part B · 07 · 골격

Murcko scaffold — 분자의 뼈대

곁사슬을 전부 떼고 고리 시스템 + linker만 남긴 것 (슬라이드 9의 파란 부분). 신약 화학자가 "이 시리즈"라고 부르는 단위와 대략 일치한다.

아스피린의 경우

CC(=O)Oc1ccccc1C(=O)O

↓ 곁사슬 제거

c1ccccc1 — 벤젠 고리 하나만 남는다

왜 중요한가

제약사 데이터는 한 골격에 곁사슬만 바꾼 유도체가 수백 개씩 들어있다. 무작위로 나누면 train과 test에 같은 시리즈가 흩어지고, 모델은 외우기만 하면 된다.

scaffold split = train과 test가 골격을 하나도 공유하지 않게 나누는 것. Part D의 핵심 도구다.

from rdkit.Chem.Scaffolds import MurckoScaffold
Chem.MolToSmiles(MurckoScaffold.GetScaffoldForMol(aspirin))   # 'c1ccccc1'
Part B · 08 · 3차원

conformer — 같은 분자, 여러 모양

SMILES는 연결만 기록한다. 3차원 좌표는 없다. 그런데 분자는 단일결합을 축으로 회전한다.

연결이 완전히 같은 분자라도, 회전 가능한 결합을 어떻게 돌리느냐에 따라 3차원 모양이 무수히 많다. 그 각각을 conformer라 부른다.

펼쳐진 모양, 접힌 모양, 꼬인 모양 — 전부 같은 분자다. 실제로는 에너지가 낮은 몇 개 모양 사이를 오간다.

결합할 때는 그중 하나의 모양으로 pocket에 들어간다. 그게 어떤 모양인지 맞히는 게 docking의 일이다.

from rdkit.Chem import AllChem
m = Chem.AddHs(mol)
AllChem.EmbedMultipleConfs(m, numConfs=50)
AllChem.MMFFOptimizeMoleculeConfs(m)
# 이제 m 안에 3D 좌표 50벌
우리는 conformer를 만들지 않는다 — Morgan fingerprint는 2D 연결만 쓴다. 3단계 co-folding 모델은 3D를 모델 내부에서 스스로 만든다. conformer 생성이 파이프라인에 등장하지 않는 이유다.

Part B · 10 · 실습

여기까지 한 화면에

from rdkit import Chem
from rdkit.Chem import AllChem, DataStructs
from rdkit.Chem.Scaffolds import MurckoScaffold

aspirin = Chem.MolFromSmiles("CC(=O)Oc1ccccc1C(=O)O")
tylenol = Chem.MolFromSmiles("CC(=O)Nc1ccc(O)cc1")

# 1. 정규화 — 중복 제거·누출 점검은 항상 이 형태로
Chem.MolToSmiles(aspirin)

# 2. 벡터화 (슬라이드 10–11)
gen = AllChem.GetMorganGenerator(radius=2, fpSize=2048)
fp_a, fp_t = gen.GetFingerprint(aspirin), gen.GetFingerprint(tylenol)

# 3. 유사도 (슬라이드 12) — 둘은 사실상 남남이라 낮은 값이 나온다
DataStructs.TanimotoSimilarity(fp_a, fp_t)

# 4. 골격 (슬라이드 13)
Chem.MolToSmiles(MurckoScaffold.GetScaffoldForMol(aspirin))   # 'c1ccccc1'

Part C · 02 · 전체 그림

co-folding은 별도 경로다

앞 슬라이드의 파이프라인을 거치지 않는다. 서열과 SMILES에서 곧장 복합체 구조를 만든다.

3단계 서열 + SMILES──▶ OpenFold3 / Boltz-2──▶ 단백질+리간드 복합체 구조 A100 필요
Boltz-2만 서열 + SMILES──▶ Boltz-2 affinity head──▶ 결합 친화도 값 우리 예측과 직접 비교
헷갈리기 쉬운 지점 셋
① AlphaFold는 리간드를 다루지 않는다. 단백질만 접는다. 위 파이프라인의 세 번째 레인이 그것이다.
② co-folding은 AlphaFold를 거치지 않는다. 예측 구조를 받아서 리간드를 끼우는 게 아니라, 처음부터 같이 만든다.
③ docking은 우리 파이프라인에 없다. 다음 슬라이드에서 왜인지 설명한다.
Part C · 03 · 왜 구조인가

서열만으로는 왜 부족한가

결합은 3차원 사건이다. pocket의 모양·전하·소수성이 결정한다.

서열이 25%만 같아도 pocket은 거의 동일할 수 있고, 서열이 90% 같아도 pocket 잔기 하나가 바뀌어 약이 안 듣게 될 수 있다. 서열 임베딩만으로는 이 구분이 어렵다.

예전

구조가 없었다

실험으로 푼 구조가 있는 단백질은 일부뿐이었다. 나머지는 구조 기반 방법을 아예 쓸 수 없었다.

지금

구조가 공짜다

AlphaFold DB에 약 2억 개 예측 구조가 있다. 무료 다운로드. 단, 예측 구조는 신뢰도가 제각각이다. 그 신뢰도가 우리 난이도 좌표가 된다.

Part C · 04 · 파이프라인 3번 레인

AlphaFold2 — 서열에서 구조로

입력
아미노산 서열 + 진화적 정보(MSA — 같은 단백질의 여러 생물종 서열을 정렬한 것)
출력
모든 원자의 3D 좌표 + 잔기별 신뢰도(pLDDT) + 쌍별 오차 예측(PAE)
핵심 발상
진화 과정에서 같이 변하는 잔기 쌍은 3D에서 가까이 있다. MSA에서 그 공변이 신호를 읽는다
한계
단백질 하나만. 리간드·이온·핵산 없음. MSA가 얕은 서열(고아 단백질, 항체 CDR)에 취약
실무
AlphaFold DB에서 받아 쓰면 GPU가 필요 없다. 1단계 전체가 CPU만으로 도는 이유
착각하기 쉬운 것 — AlphaFold는 "이 단백질이 어떻게 접히는가"를 예측하지, "이 약이 붙는가"를 예측하지 않는다. 결합 예측은 그 위에 따로 올려야 한다.
Part C · 05 · 신뢰도

pLDDT — 구조가 스스로 붙이는 신뢰도

잔기마다 0~100. AlphaFold가 자기 예측에 스스로 매기는 점수다. 이 프로젝트 주제와 직결된다.

> 90매우 높음 — 곁사슬까지 신뢰
70 – 90신뢰 — 뼈대는 맞음
50 – 70낮음 — 조심
< 50매우 낮음 — 대개 무질서 영역

전체 평균 pLDDT는 쓰지 않는다. 단백질 전체가 90이어도 pocket이 60이면 우리 목적에 쓸모없다. 반대도 성립한다.

# AlphaFold DB 파일에서는 B-factor 컬럼이 곧 pLDDT다
plddt = {r.id[1]: next(r.get_atoms()).get_bfactor() for r in chain}
coord3 = mean(plddt[i] for i in pocket_residues)
함정 — B-factor = pLDDT는 AlphaFold DB 파일에서만 참이다. 실험 PDB에서 그 컬럼은 진짜 B-factor(원자 흔들림)다. 두 출처를 섞으면 조용히 재앙.
Part C · 06 · 신뢰도

PAE — 두 부분의 상대 위치는 맞는가

PAE(predicted aligned error)는 잔기 쌍마다 예측 오차를 준다. "잔기 i를 기준으로 정렬했을 때 잔기 j의 위치가 몇 Å 틀릴까". 단위는 Å, 낮을수록 좋다.

도메인 두 개가 각각은 완벽하게 접혔는데(pLDDT 95) 서로의 배치가 엉망일 수 있다. pLDDT는 이걸 못 잡고 PAE만 잡는다.

pocket이 두 도메인 경계에 걸쳐 있으면, PAE가 나쁠 때 pocket 기하 자체가 틀린다. pocket pLDDT가 높아도 소용없다.

AF DB에서 PAE는 구조 파일과 별개인 JSON으로 받는다.

진할수록 오차 낮음. 대각선 블록 둘 = 잘 접힌 도메인 둘. 블록 사이가 밝다 = 상대 배치를 모른다.

Part C · 07 · pocket

pocket 검출 — 약이 들어갈 구멍 찾기

구조를 받았다고 pocket을 아는 게 아니다. 어느 잔기들이 pocket을 이루는지 따로 계산해야 한다.

fpocket

기하학적 방법. 단백질 표면에 작은 구를 굴려 넣어 오목한 공간을 찾는다. 빠르고 학습 가정이 없다.

P2Rank

머신러닝 방법. 알려진 결합 부위로 학습해 "약이 붙을 만한" 지점에 점수를 매긴다. 정확도가 더 높다.

둘 다 CPU에서 초 단위로 끝난다. 출력은 pocket마다 이 pocket을 이루는 잔기 번호 목록. 여기서 난이도 좌표 두 개가 나온다.

좌표 ③

구조 신뢰도

이 잔기 목록으로 pLDDT를 마스킹해 평균, PAE 부분행렬을 평균

좌표 ④

구조 가용성

이 pocket 영역을 덮는 실험 PDB 구조가 있는가. 0=없음 / 1=apo만 / 2=holo 있음

Part C · 08 · 파이프라인 4번 레인

Foldseek 3Di와 SaProt — 구조를 문자열로

3Di 알파벳

잔기 하나의 국소 뼈대 기하를 20글자 중 하나로 인코딩한다. 3D 구조가 아미노산 서열과 같은 길이의 문자열이 된다.

원래는 구조 검색을 서열 검색만큼 빠르게 하려고 만든 것. 부산물이 훨씬 유용해졌다.

아미노산  M K T A Y I A K Q R Q
3Di       d p v v c q a d d p k

SaProt

(아미노산, 3Di) 쌍을 하나의 토큰으로 묶은 어휘로 학습한 protein language model. 파이프라인에서 ESM-2 자리에 그대로 끼워넣을 수 있다.

3D 좌표 처리도, docking도, conformer 생성도 없다. 구조를 쓰는 가장 싼 방법이다.

2단계의 실제 질문

ESM-2(서열만) vs SaProt(서열+구조). 어느 난이도 구간에서 구조가 실제로 기여하는가? 구조가 도움이 안 된다는 결과가 나와도 그대로 보고한다 — 계획서 리스크 표에 이미 명시돼 있다.

Part C · 09 · 우리가 안 쓰는 것

docking — 고전 방식

단백질 구조는 고정해두고, 리간드를 회전·이동시켜 가장 잘 맞는 자세(pose)를 찾은 뒤 점수를 매긴다.

탐색

리간드의 회전 가능한 결합을 돌려가며 수만~수백만 자세를 생성 (슬라이드 14의 conformer)

채점

물리 기반 또는 경험적 scoring function으로 각 자세에 점수

출력

최고점 자세 + 점수. 그 점수를 결합 친화도의 대용으로 쓴다

알려진 한계

  • 단백질이 안 움직인다 — 실제로는 리간드가 들어오면서 pocket이 변형된다 (induced fit)
  • scoring function이 부정확하다 — 자세는 맞혀도 친화도 순위는 못 맞히는 일이 흔하다
  • 물리적으로 불가능한 pose — PoseBusters(2024)는 딥러닝 docking 결과 상당수가 결합 길이·입체화학이 깨진 구조임을 보였다
안 쓰는 이유 — 자원 대비 신호가 약하고, 우리 질문은 "어떤 결합 예측이 정확한가"가 아니라 "모델이 자기 불확실성을 아는가"다.
Part C · 10 · co-folding

co-folding — 같이 접는다

단백질을 먼저 접고 리간드를 나중에 끼워넣는 대신, 단백질과 리간드를 하나의 모델에서 동시에 배치한다.

왜 더 나은가

  • 리간드가 있는 상태의 pocket 모양을 직접 만든다 — induced fit이 자연스럽게 들어온다
  • 탐색+채점 2단계가 아니라 생성 1단계. scoring function의 부정확성을 우회
  • 이온·보조인자·핵산도 같은 틀에서 다룬다

대가

  • 느리고 무겁다. 쌍 하나에 GPU 수십 초~수 분. 데이터 전체에 돌리면 예산이 붕괴한다
  • 학습 데이터에 없던 화학종에 약하다
  • 자신 있게 그럴듯한 틀린 구조를 낸다 — 우리 주제와 정확히 같은 실패 양상
계획서의 결정 — co-folding은 전체 데이터에 돌리지 않는다. 3단계 도전 과제로 격리해, 실패해도 논문과 일정이 무손상이도록 설계했다.
Part C · 11 · 모델 계보

AlphaFold3와 오픈 재현의 물결

AlphaFold3 (2024)

단백질만이 아니라 리간드·핵산·이온을 한 모델에서 다룬다. MSA 의존을 줄이고 diffusion 기반 구조 생성으로 전환. 최초의 대규모 co-folding 모델.

문제 — 코드와 가중치 접근이 제한적이다. 학술적으로 재현·감사가 어렵다.

그래서 무슨 일이 벌어졌나

여러 그룹이 AF3급 co-folding 모델을 오픈 라이선스로 재현하기 시작했다. 우리 3단계는 그 결과물 두 개를 쓴다.

  • Boltz-2 — 오픈 가중치, affinity head 내장
  • OpenFold3 — Apache 2.0, 학습 데이터 공개

이 물결이 우리에게 중요한 이유는 성능이 아니라 감사 가능성이다. 학습 데이터를 모르면 우리 test set과 겹쳤는지 확인할 방법이 없다.

Part C · 12 · Boltz

Boltz-2 — 구조와 친화도를 한 번에

출신
MIT Jameel Clinic 계열 오픈소스 프로젝트. Boltz-1은 AF3급 co-folding의 오픈 재현
추가분
binding affinity head — 구조만 내는 게 아니라 결합 세기를 직접 예측한다
주장
물리 기반 골드 스탠다드(FEP)에 근접한 정확도를 훨씬 적은 연산으로
라이선스
오픈 가중치 배포
왜 중요
우리 태스크와 정확히 같은 것을 예측한다. 조건 A의 상한선을 보여주는 강력한 비교 대상
3단계 착수 전 반드시 확인 (블로킹)
① Boltz-2 affinity head는 ChEMBL·BindingDB로 학습됐다. 우리 test set이 TDC BindingDB다 → 학습 데이터와 겹칠 가능성이 크다. 학습 cutoff 기준으로 중복 제거하지 않으면 train-on-test가 된다.
② 버전·라이선스 상태가 빠르게 바뀐다. 오픈 가중치 버전으로 고정하고 결과표에 버전 문자열을 명기한다.
Part C · 13 · OpenFold3

OpenFold3 — 감사 가능한 쪽

OpenFold 컨소시엄의 AF3 재현. Apache 2.0이고 학습 데이터 구성이 공개된다.

계획서가 이쪽을 3단계 1순위로 둔 이유는 성능이 더 좋아서가 아니다. "우리 test set이 학습에 들어갔는가"를 직접 확인할 수 있어서다.

경로 설계

둘을 나란히 두는 이유

경로 ① OpenFold3 — Apache 2.0, 타겟 50개
경로 ② Boltz-2 — 오픈 가중치, 200쌍, 선택

한쪽 라이선스나 공개 상태가 막혀도 도전 실험이 살아남는다.

정직한 고지 — Boltz와 OpenFold3의 최신 버전 상태·라이선스는 빠르게 바뀐다. 이 슬라이드를 사실로 확정하지 말고, 2주차 DOI·링크 전수 검증 때 직접 열어서 확인한 뒤 3단계 경로를 결정한다.

Part D · 01 · split

split이란 무엇인가

데이터를 train / validation / test로 나누는 규칙.
진짜 질문은 무엇을 기준으로 나누느냐이다.

DTI 데이터는 사실상 행렬이다. 행 = 단백질 타겟, 열 = 화합물, 셀 = 측정된 결합 친화도. 대부분의 셀은 비어 있다 (측정된 적 없음).

그래서 "무작위로 20%를 뗀다"가 애매해진다. 셀을 뗄 것인가, 열을 뗄 것인가, 행을 뗄 것인가? 셋은 완전히 다른 문제를 만든다.

Part D · 02 · 함정

random split은 거짓말을 한다

화합물 A가 train에 30번, test에 5번 등장한다고 하자. 모델은 A의 평균 활성만 외워도 test에서 잘 맞힌다. 타겟도 마찬가지다.

결과: AUROC 0.90짜리 논문이 실제 신약 발굴 상황에서는 무작위와 다를 바 없다.

Wallach & Heifets, JCIM 2018 — "대부분의 리간드 기반 벤치마크는 일반화가 아니라 암기를 보상한다". 부록 A 필독.

이 프로젝트의 출발점

난이도는 사후 라벨이 아니다

어떤 split을 쓰느냐가 곧 문제의 난이도를 결정한다. 그리고 우리는 그 난이도를 모델과 무관하게, 예측 전에 측정할 수 있다 — Tanimoto, 서열 identity, pocket pLDDT.

그게 이 벤치마크의 유일한 고유 자산이다.

Part D · 03 · 네 가지 split

같은 데이터, 네 가지 난이도

train test 데이터 있음, 미사용 제외

행 = 타겟, 열 = 화합물. 오른쪽으로 갈수록 어렵다. 계획서는 네 가지를 전부, 항상 함께 보고하도록 못박았다. 하나만 고르면 반드시 유리한 것을 고르게 되기 때문이다.

Part D · 05 · 동결

split은 4주차에 얼려서 다시 건드리지 않는다

실무 이유

split을 바꾸면 학습·평가·난이도 좌표·보정이 전부 무효가 된다. 5~13주차 결과를 통째로 다시 돌려야 한다. 계획서가 유일하게 되돌릴 수 없는 지점이라 부른 곳.

통계적 이유

결과를 본 뒤 split을 조정하면 그건 더 이상 test set이 아니다. 사전 등록의 최소 형태가 split 동결이다.

cold split = dataset shift — 이건 단순한 난이도 조절이 아니다. train과 test의 분포가 달라지므로, conformal prediction이 요구하는 exchangeability 가정이 깨진다. 커버리지 보장이 어디서 무너지는지가 이 프로젝트의 연구 질문 그 자체다.
